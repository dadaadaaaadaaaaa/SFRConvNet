# Exp2 leave-one-galaxy-out workflow

Run commands from the project root.

## 1. Prepare every available fold

```powershell
python Experiment/prepare_data.py --experiments exp2 --oversample=true
```

Only configured disk-galaxy directories that actually contain processed `.h5`
files participate. With the current data this produces three folds, holding out
Fiducial, Fiducial4, and Fiducial7 in turn. A future fourth valid galaxy will
automatically produce a fourth fold.

To prepare only selected held-out galaxies:

```powershell
python Experiment/prepare_data.py --experiments exp2 --held-out-galaxy fiducial_4
```

The command rewrites the Exp2 fold manifest to list the folds generated by that
invocation.

Other cache-preparation selections are also supported:

```powershell
python Experiment/prepare_data.py --experiments exp1 exp2
python Experiment/prepare_data.py --experiment exp3
```

## 2. Train folds

Train every fold listed in the manifest:

```powershell
python Experiment/run_train.py --experiments exp2
```

To run the same folds without feeding transformed KS-law SFR into SFRConvNet
through FiLM:

```powershell
python Experiment/run_train.py --experiments exp2 --use-film=false
```

This does not require regenerating the PT caches. The KS value remains in the
cache for baseline evaluation, but `SFRConvNet(use_film=False)` does not use it
in its forward computation. Result names receive a `_NoFiLM` suffix.

Train only one listed fold:

```powershell
python Experiment/run_train.py --experiments exp2 --held-out-galaxy fiducial_4
```

Each fold receives a distinct cache prefix, experiment name, result directory,
and checkpoint. Training aborts if the actual train/validation/test groups do
not equal the recorded in-domain groups, if `out.pt` is missing, or if the
actual held-out group overlaps a training group.

New SFRConvNet result directories use concise names such as
`Exp2_LOOfiducial4_20260810_134618`.

The same SFRConvNet shorthand is available for later numbered experiments:

```powershell
python Experiment/run_train.py --experiment exp3
python Experiment/run_train.py --experiments exp3 exp4
```

Explicit keys from `.config/ExperimentSetting.json` remain supported.

## 3. Analyze domain-separated results

Analyze the latest completed model from every leave-one-out fold:

```powershell
python VisualScripts/ResultAnalysis/analyze_exp2.py --all-folds
```

To calculate every domain's metrics while suppressing the two in-domain
reference domains' figures:

```powershell
python VisualScripts/ResultAnalysis/analyze_exp2.py --all-folds --plot-in-distribution=false --plot-in-domain=false
```

Or analyze an explicit result directory:

```powershell
python VisualScripts/ResultAnalysis/analyze_exp2.py --result-dir "Results\<result-directory>"
```

The analysis writes separate outputs for:

- `in_dist_test_predictions.csv`: random in-domain `test.pt` reference;
- `held_out_test_predictions.csv`: full normalized `out.pt`;
- `raw_in_domain_predictions.csv`: complete trajectories of training galaxies;
- `raw_held_out_predictions.csv`: complete trajectory of the unseen galaxy;
- `metrics_exp2.csv`: RMSE, MAE, R2, and outlier fraction for all four domains.

SFR-history and cumulative-SFR figures are generated separately for every raw
in-domain and held-out trajectory. The analysis repeats the actual group-label
checks before prediction.

Figures are written to an option-specific directory so rerunning with plotting
disabled cannot be confused with older images: `figures_all`,
`figures_held_out`, `figures_held_out_in_dist`, or
`figures_held_out_in_domain`.

The notebook `Results_stat_Exp2_new.ipynb` provides the same all-fold analysis,
plot switches, per-fold metric table, and cross-fold held-out summary
interactively. The older `Results_stat_Exp2.ipynb` is retained only as a legacy
record and should not be used for new leave-one-out results.
